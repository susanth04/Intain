## Objective

Predict multiple loan performance outcomes on a mortgage panel dataset (loan × month observations):

1. `next_3m_delinquency_flag` — will this loan become delinquent within 3 months?
2. `next_6m_delinquency_flag` — within 6 months?
3. `next_12m_default_flag` — will this loan default within 12 months?
4. `next_12m_prepayment_flag` — will this loan prepay within 12 months?
5. `next_state` — what state will this loan be in next month?

Plus: anomaly/exception detection, survival modeling, and scenario stress testing.

---

## Data

**Source**: Synthetic dataset generated via `src/data/generate_synthetic_data.py`.  
**Schema**: Loan × month panel with ~30 feature columns + 7 target columns.  
**Size**: 5,000 loans × up to 30 months = ~100,000–150,000 panel rows (configurable).

**Key schema fields**:
- Static: `credit_score_band`, `ltv_band`, `dti_band`, `state`, `loan_purpose`, `vintage`
- Dynamic: `current_status`, `days_past_due`, `current_balance`, `interest_rate`, `modification_flag`
- Targets: `next_3m_delinquency_flag`, `next_6m_delinquency_flag`, `next_12m_default_flag`, `next_12m_prepayment_flag`, `next_state`

## Model Architecture

### Binary Targets (delinquency/default/prepayment)

| Component | Description |
|---|---|
| Baseline | Logistic Regression (C=0.1, class_weight=balanced) |
| Improved | LightGBM (n_estimators=400, num_leaves=63, early stopping on val) |
| Calibration | Isotonic regression (CalibratedClassifierCV with cv="prefit") |
| Imbalance handling | `class_weight="balanced"` — preferred over SMOTE to avoid synthetic leakage |

### Next State (multiclass)
LightGBM with `objective="multiclass"`, same hyperparameters, LabelEncoder for 7 states.

### Survival Model
- Kaplan-Meier curves by credit band
- Cox Proportional Hazards (lifelines): features `credit_enc`, `ltv_enc`
- Competing risks: Aalen-Johansen estimator (default vs. prepaid)
- Discrete-time hazard: Logistic Regression on person-period records

### Anomaly Detection
- Rules layer: execute `validation_rules.json` (VR001–VR006)
- ML layer: Isolation Forest (contamination=0.05, 200 trees)
- Combined: `0.4 × rule_score + 0.6 × ml_score`

---

## Validation Method

**Split**: Time-aware by `month_index`.
- Train: months 1–20
- Validation: months 21–25
- Test: months 26–30

**Leakage controls**:
1. Lag features computed on the FULL panel BEFORE splitting (no look-ahead)
2. Forward-looking targets derived from simulated future trajectory, not from test rows
3. Automated leakage check: asserts no feature has |r| > 0.99 with any target in train set
4. Printed proof statement: "✅ No loan_id leakage" on every pipeline run

## Limitations

1. **Synthetic data**: All evaluation is on synthetic data generated by the same process as the training data. Real-world performance may differ significantly when organizer data is provided.
2. **Static credit bands**: The synthetic data treats credit_score_band as static per loan. In reality this can change (modifications, credit events). If real data is dynamic, the feature engineering must be updated.
3. **Censoring treatment**: Loans still active at the data cutoff are treated as censored in the survival model. If censoring is non-random (healthier loans survive longer), the KM estimates are optimistic.
4. **LLM copilot**: Operates in offline stub mode unless `OPENAI_API_KEY` is set. Stub responses are template-based and should not be used for actual decisions.
5. **Class imbalance**: Default and prepayment events are rare (2–8% base rate). Despite calibration, the model may still over-predict the majority class for very rare events.

## Known Failure Modes

| Failure Mode | Description | Mitigation |
|---|---|---|
| Lookback window truncation | Loans in their first few months have no lag features | Fill NaN lags with median; flag young loans as high-uncertainty |
| Terminal state misclassification | Model may predict "Current" for loans already in "Default" | Post-process: if current_status ∈ {Default, Prepaid, Closed}, force next_state = same |
| Balance outliers | Injected 0.5% extreme outliers cause Isolation Forest to over-flag | Cap balance_utilisation at 3.0 in feature engineering |
| LLM hallucination | Copilot may fabricate field values or rules not in context | 3 documented cases in `copilot_demo.md`; all outputs labeled "AI-generated" |
| Distribution shift | PSI > 0.25 features in train→test drift analysis | Monitor PSI per feature; retrain if significant drift detected |

## Responsible AI Controls

- All predictions come from trained ML models, not from LLM calls
- LLM outputs are labeled "AI-generated recommendation — not a decision" throughout
- Every LLM call is logged to `ai_dev_log/copilot_prompt_log.jsonl`
- Documented failure cases of LLM copilot are included in `reports/copilot_demo.md`
- Model card includes known failure modes and limitations (this document)
- Leakage controls are automated and printed on every pipeline run
